Application Name
travel-knowledge-mcp-server
Objective

Build an Enterprise-grade Model Context Protocol (MCP) Server named travel-knowledge-mcp-server using the official MCP Python SDK (FastMCP).

The purpose of this project is to demonstrate how enterprise organizations expose Knowledge Retrieval (RAG) as a dedicated MCP capability.

This project is not responsible for ingesting documents.

Knowledge ingestion is handled by a separate application:

travel-knowledge-ingestion

which loads documents into ChromaDB.

This MCP server is responsible only for retrieving knowledge.

The project should emphasize:

Enterprise Architecture
Clean Architecture
SOLID Principles
Strategy Pattern
Factory Pattern
Retrieval Pipeline
Dependency Injection
Pluggable Retrieval Algorithms

rather than simply querying ChromaDB.

Overall Architecture
                    travel-knowledge-ingestion
                               │
                               ▼
                           ChromaDB
                               ▲
                               │
                   travel-knowledge-mcp-server
                               │
                               ▼
                    OpenAI Agents SDK

The ingestion pipeline owns indexing.

The MCP server owns retrieval.

Responsibilities

This MCP server must:

expose MCP Tools
expose MCP Resources
expose MCP Prompt Templates
retrieve knowledge
return structured DTOs

This project must NOT:

perform ingestion
chunk documents
generate embeddings
load PDFs
update vector database

Those belong to the ingestion project.

Deliverables

Generate a complete runnable project.

The application should run using:

uv sync

uv run python app/main.py

It should connect to the existing ChromaDB instance, generate query embeddings, retrieve relevant documents using the configured retrieval strategy, optionally rerank them, and return structured Pydantic DTOs through MCP Tools.

Learning Goals

By completing this project, the implementation should demonstrate:

Enterprise MCP server architecture for knowledge retrieval
Separation of ingestion and retrieval into independent services
Retrieval Pipeline Pattern
Strategy Pattern for query processing, retrieval, vector stores, and reranking
Factory Pattern for runtime strategy selection
Clean Architecture with dependency injection
Configuration-driven retrieval behavior
Pydantic DTOs as MCP request/response contracts
A design that can evolve from simple vector similarity search to advanced enterprise RAG techniques—such as Hybrid Search, Self-Query Retrieval, Parent-Document Retrieval, Multi-Query Retrieval, HyDE, Contextual Retrieval, and Cross-Encoder Reranking—without changing the MCP layer or business services.
